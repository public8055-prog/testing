# Security review — current implementation

Scope: local source/configuration, authorization/concurrency controls and targeted tests. This is a defensive implementation review, not an independent penetration test or a guarantee against compromise. Exact integrated build/browser outcomes and dates remain in [VALIDATION.md](VALIDATION.md); historical backup evidence remains in [BACKUPS.md](BACKUPS.md).

## Current controls

| Area | Implemented control / source |
| --- | --- |
| Secrets | Server-only runtime secrets; protected one-shot seed; no embedded administrator credential; Docker/standalone trace sanitization; explicit private/configuration-path 404. `scripts/security-audit.mjs` reports candidate names/locations rather than secret values. |
| Passwords | Argon2id (64 MiB, t=3, p=1) with random salt. Both old scrypt formats verify and upgrade with compare-and-set/reset-race protection. Per-process work limit: 2 active, 8 queued, 3-second wait. `lib/password-hashing.ts`, `lib/auth.ts`. |
| Sessions | Signed HS256 access JWT lasting 15 minutes; opaque rotating refresh lasting 7 days; HttpOnly/SameSite=Lax cookies, Secure in production. Redis hash/reuse state plus independently revocable Mongo anchor; current database role/status required on every authenticated lookup. `lib/auth-sessions.ts`, `lib/auth-state.ts`. |
| Auth abuse | Redis limits: 5 login attempts/15 minutes per IP and normalized identifier, separate 15-minute lockout after 5 failed credentials, dummy verification for unknown accounts, generic errors and audit events. Public registration cannot assign privilege. |
| Shared/admin access | Shared `/login`; canonical `SUPER_ADMIN/ADMIN/PROVIDER/CUSTOMER`; anonymous/nonadmin administration routes 404. Super-admin-only role changes, self/last-admin protections, transaction rechecks and audit records. `proxy.ts`, `lib/roles.ts`, `lib/admin-management.ts`. |
| Refresh clients | Cross-tab Web Locks with IndexedDB lease fallback; proactive admin recheck preserving 404; one 401 replay for other same-origin protected APIs; no recursion into auth endpoints or retries of business/network failures. `lib/session-client.ts`. |
| Recovery | Hashed 30-minute single-use tokens, generic accepted requests, real configured mail adapter only, anchor/family revocation and old-password race guard. Masked accessible password fields. `lib/password-reset.ts`. |
| Ownership | Customer/provider/business queries enforce actual ownership or memberships; queue assignment/status mutations check active stored actors/providers. Token labels are references, not credentials. |
| Input / XSS | Zod schemas/primitive IDs; byte-bounded JSON; React text escaping; same-origin mutations; nonce production CSP; no unsafe-eval in production. Stored review-ID operator injection was repaired. |
| Uploads | Authenticated bounded 5 MiB uploads; image signature/decode/pixel limits and re-encoding; private provider ownership/admin checks; Mongo GridFS; provider PDFs served as attachments. `lib/uploads.ts`, upload/document routes. |

Superseded evidence cannot be approved; legacy unqualified active profiles return to review on initialization. `lib/admin-providers.ts`, `lib/provider-identity.ts`. |

| CORS / transport | Helmet baseline headers, no wildcard credentialed CORS, strict configured origins, loopback protocol/host checks, authenticated WebSocket bridge, empty update hints and bounded stream lifetime. `scripts/gateway.mjs`, `proxy.ts`. |
| Limits / cache | Redis atomic sliding windows, hashed key identities and Retry-After; security-dependent writes fail closed. Public catalogue cache has bounded lifetime/generation invalidation; private responses are no-store. |
| Queue concurrency | Per-service/day Redis candidate with Mongo durable counter/allocation, transactionally issued token, versioned transitions, record-scoped IDs and idempotent booking requests. Redis loss cannot recycle a committed allocation. |
| Payments | Authoritative amounts/currency, ownership, pinned gateways, signed callbacks, deduplication and guarded refunds; external network calls outside Mongo retries. Cash requires a separate auditable receipt action. |
| Consent / contact | Explicit terms/privacy/adult consent with version/date, no fabricated historical consent; contact consent/honeypot/rate limits and 90-day TTL. Attendance does not collect GPS. Optional booking GPS has separate participant consent, browser permission and bounded retention; no microphone/camera collection. |
| Booking maps / GPS | Current database ownership/assignment and administrator roles gate every read; transaction fences, session IDs, sequence/timestamp checks, rate limits and no-store responses protect updates. Administrators cannot impersonate participant GPS. Latest-point retention is seven days; four-hour sharing sessions; reassignment/closure removes provider access; explicit point removal revokes the session. Address and backups have separate retention. Map tiles require a user loading choice. |

## Material limits and required operating controls

- Rotate any password previously shared through conversation before public exposure. MFA and email ownership verification are not implemented. Restrict sensitive operations through an independently authenticated gateway where appropriate.
- Signing-key rotation alone is not full session revocation: a still-active refresh family can mint a replacement JWT. Incident response must revoke affected Mongo session anchors/Redis families and rotate leaked passwords/keys.
- Refresh rotation deliberately rejects reuse, including uncontrolled concurrent use. Application clients coordinate across tabs; custom clients must serialize refresh. Live streams can remain open until the bounded reauthentication timeout, but carry only update hints; every private data fetch still authenticates.
- The local data containers have neither authentication/TLS nor failover redundancy. Production requires private networking, least-privilege authenticated TLS services, encryption/key management and tested recovery. The shared startup validator used by container entrypoints, host-run `npm start` and `npm run worker` requires authenticated TLS MongoDB and password-authenticated `rediss://` outside explicit loopback preview, and rejects TLS/certificate-verification bypasses. Its six focused configuration tests pass; it does not connect to verify real credentials, certificates or infrastructure policy.
- Both Linux images built and passed nine local runtime checks, including startup, mapped-port origin handling, authentication, non-root operation, private-file exclusion and graceful shutdown. This does not establish production recovery, network policy or OS-image vulnerability status. Verify the image targets on the deployment host. Only the web service has a Compose readiness health check; worker progress and backup/maintenance failures require separate monitoring.
- Set `TRUST_PROXY` only for a gateway behind a real proxy that replaces untrusted client headers. The launcher trusts forwarding only on its private Next child. Direct Next development without trusted forwarding shares a fallback rate-limit identity. Never enable arbitrary-header trust on a public listener.
- Keep previews behind actual access controls. `PUBLIC_LAUNCH_READY=false`, draft labels and robots metadata do not disable registration/booking or protect private data. Serve deployment output rather than the workspace.
- Live gateway credentials/signatures, actual mail delivery, external TLS/DNS and production failover/load remain separately unverified. Automated provider responses are simulations; an unpaid reservation is not revenue.
- Reset delivery after the response is not a durable mail queue. Delivered links intentionally include a token in the URL; protect mailbox/link access and redact reset query parameters in hosting/proxy/error logs. A generic request result does not prove delivery.
- PDF signature/EOF checks are not antivirus or content-disarm validation. Add scanning/quarantine for the intended document risk. Public banner images and private provider evidence have different access policies; neither replaces image/document rights review.
- Soft deletion retains personal/history records. Privacy erasure and retention require operator review across MongoDB, GridFS, mail and backups. Contact TTL can expire unresolved requests; staff must monitor them. Workforce retention settings do not automatically erase history.
- Audit rows are application records, not an externally immutable archive. A privileged database operator can alter them. Restrict database access and configure external alerting, operational log retention and incident response.
- The bounded local backup utility is not offsite backup or point-in-time recovery. Supervise the worker, protect a recovery key copy, set retention/capacity alerts and exercise restoration.
- No Git history was available in this checkout for historical secret scanning. The heuristic source scanner and time-specific dependency audit cannot prove the absence of every secret or vulnerability. Scan full history once available and rotate real exposures.
- Browser traces can contain synthetic auth cookies and private test records. Keep artifacts/backups/environment files private. Never attach those files to a public report without careful sanitization.
- Automated viewport/axe checks are not complete WCAG conformance or actual Safari/device validation. Test macOS/iOS Safari, keyboard/screen readers and real mobile keyboards separately. Native Windows Playwright WebKit cookie metadata has a known Lax-reporting limitation; preserve actual server Set-Cookie checks and distinguish that engine from Safari.
- The cached-read p95 <300 ms goal and concurrency tests do not establish production or 10,000-user capacity. Hash concurrency limits are per process; size aggregate resource use and edge protections for the replica count.

Business identity, support/grievance delivery, legal review and image provenance remain unverified operator requirements. Empty source defaults and draft labels avoid invented details but do not satisfy complete live business configuration. Optional future analytics requires separate authorization and consent work; analytics is currently off. No blanket security, legal, uptime, copyright or production-readiness claim is made.
